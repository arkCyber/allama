# Allama 测试计划

## 测试目标

验证 Allama 项目的航空航天级别安全特性和功能完整性，确保系统在各种场景下都能稳定运行。

## 测试范围

### 1. API端点测试
**目标**: 验证所有API端点的功能正确性

**测试项**:
- GET /api/tags - 列出可用模型
- POST /api/generate - 生成文本
- POST /api/chat - 聊天完成
- POST /api/embed - 嵌入生成
- GET /api/ps - 列出运行中的模型
- POST /api/show - 显示模型详情
- GET /api/version - 版本信息
- POST /v1/chat/completions - OpenAI兼容端点
- POST /v1/completions - OpenAI兼容端点
- POST /v1/embeddings - OpenAI兼容端点
- 无效端点404测试
- 无效JSON 400测试

**预期结果**: 所有有效端点返回200，无效输入返回相应的错误码

---

### 2. 速率限制测试
**目标**: 验证基于真实IP的速率限制功能

**测试项**:
- 单个请求正常处理
- 快速发送70个请求（超过60限制）触发速率限制
- 等待60秒后速率限制恢复
- 不同IP的独立速率限制（需要多台机器）
- 速率限制器HashMap清理机制

**预期结果**: 
- 正常请求成功
- 超过限制返回429
- 时间窗口后恢复
- 不同IP独立计数

---

### 3. 并发处理测试
**目标**: 验证并发请求处理能力

**测试项**:
- 并发发送20个GET请求
- 并发发送20个POST请求
- 并发发送10个生成请求
- 压力测试 - 100个并发请求
- 并发限制中间件验证

**预期结果**:
- 所有并发请求正确处理
- 成功率 >= 95%
- 无死锁或崩溃

---

### 4. 输入验证测试
**目标**: 验证输入验证机制

**测试项**:
- 正常输入长度（100字符）通过
- 超长输入（150K字符）被拒绝
- 正常消息数量（10条）通过
- 超多消息（150条）被拒绝
- 正常请求大小（1MB）处理
- 超大请求（15MB）被拒绝
- 空输入被拒绝
- 无效JSON被拒绝
- 缺少必需字段被拒绝
- 模型名称白名单验证

**预期结果**:
- 有效输入正常处理
- 无效输入返回400错误
- 超过限制的输入被拒绝

---

### 5. 优雅降级测试
**目标**: 验证优雅降级机制

**测试项**:
- 正常情况下服务可用性
- 超时保护机制
- 降级模式切换
- 降级模式下的响应
- 故障恢复机制
- 互斥锁死锁防护
- 审计日志记录
- 错误处理和恢复
- 并发限制保护
- 资源监控

**预期结果**:
- 正常情况服务可用
- 异常情况优雅降级
- 故障后自动恢复
- 审计日志完整记录

---

## 测试环境

### 硬件要求
- CPU: 4核心以上
- 内存: 8GB以上
- 磁盘: 10GB可用空间

### 软件要求
- 操作系统: macOS/Linux
- Rust: 1.70+
- curl: 用于API测试
- jq: JSON处理（可选）

### 环境变量
- `ALLAMA_HOST`: 服务器地址（默认: 127.0.0.1）
- `ALLAMA_PORT`: 服务器端口（默认: 11434）
- `TEST_MODEL`: 测试使用的模型名称（默认: llama3.2）
- `OLLAMA_NUM_PARALLEL`: 并发处理数量（默认: 1）
- `OLLAMA_MAX_LOADED_MODELS`: 最大加载模型数（默认: 3）
- `OLLAMA_MAX_QUEUE`: 最大队列大小（默认: 512）

### 测试数据准备
1. 确保至少有一个模型已下载并可用
2. 准备测试用的提示词和对话数据
3. 准备不同长度的输入数据用于边界测试
4. 准备无效JSON和格式错误的数据用于错误测试

---

## 测试执行流程

### 前置准备
1. 构建 Allama: `cargo build --release`
2. 设置测试脚本执行权限: `chmod +x tests/integration/*.sh`
3. 配置环境变量（可选）:
   ```bash
   export ALLAMA_HOST=127.0.0.1
   export ALLAMA_PORT=11434
   export TEST_MODEL=llama3.2
   ```
4. 启动服务器: `./target/release/allama serve`
5. 确保测试模型已加载（可选）

### 运行测试
```bash
# 运行所有测试
cd tests/integration
./run_all_tests.sh

# 运行单个测试
./api_tests.sh
./rate_limit_test.sh
./concurrency_test.sh
./input_validation_test.sh
./graceful_degradation_test.sh
```

### 测试报告
测试报告将自动生成在 `tests/docs/test_results_<timestamp>.md`

### 测试结果分析
测试报告包含以下内容：
- 每个测试的执行状态（通过/失败/跳过）
- 详细的错误信息和日志
- 测试执行的统计数据
- 性能指标（响应时间、成功率等）
- 建议和改进措施

### 故障排除
如果测试失败，请检查：
1. 服务器是否正常运行: `curl http://127.0.0.1:11434/api/tags`
2. 测试脚本是否有执行权限: `ls -l tests/integration/*.sh`
3. 环境变量是否正确配置: `echo $ALLAMA_HOST`
4. 网络连接是否正常: `ping 127.0.0.1`
5. 查看服务器日志获取详细错误信息

## 测试标准

### 通过标准
- 所有API端点测试通过
- 速率限制正常触发和恢复
- 并发处理成功率 >= 95%
- 输入验证正确拒绝无效输入
- 优雅降级机制正常工作

### 失败标准
- 任何核心API端点失败
- 速率限制不工作
- 并发处理成功率 < 80%
- 输入验证不工作
- 系统崩溃或死锁

---

## 已知限制

1. **多IP速率限制测试**: 需要多台机器，当前跳过
2. **超时保护测试**: 需要控制服务器响应时间，当前跳过
3. **降级模式测试**: 需要手动触发降级，当前跳过
4. **HashMap清理测试**: 需要服务器日志访问，当前跳过
5. **死锁防护测试**: 需要服务器日志访问，当前跳过
6. **审计日志测试**: 需要服务器日志访问，当前跳过
7. **资源监控测试**: 需要服务器监控API，当前跳过
